## 5. bootcmd 拆解

`bootcmd` 原始值：

```text
run findfdt;run findtee;mmc dev ${mmcdev};mmc dev ${mmcdev}; if mmc rescan; then if run loadbootscript; then run bootscript; else if run loadimage; then run mmcboot; else run netboot; fi; fi; else run netboot; fi
```

拆解：

```text
1. run findfdt
   选择设备树文件。当前 fdt_file 已经是 100ask_imx6ull-14x14.dtb。

2. run findtee
   当前环境中 findtee 未定义，所以启动日志会出现 Error: "findtee" not defined。该错误目前不阻塞启动。

3. mmc dev ${mmcdev}
   选择 mmcdev=1。

4. mmc rescan
   扫描 MMC 设备。

5. run loadbootscript
   尝试从 mmc ${mmcdev}:${mmcpart} 加载 boot.scr。

6. run loadimage
   如果没有 boot.scr，则执行 loadimage，从 /boot/zImage 加载 Kernel 到 loadaddr=0x80800000。

7. run mmcboot
   设置 mmcargs，加载 dtb，然后执行 bootz 启动 Kernel。

8. run netboot
   只有 MMC 扫描或 Kernel 加载失败时才走网络启动。
```

关注点：

- Kernel 从哪里加载：SD / eMMC / NAND / TFTP。
- dtb 从哪里加载。
- 使用 `bootz`、`bootm` 还是其他启动命令。

判断：

```text

Kernel 日志输出串口：ttymxc0，115200。
是否涉及 NFS：否，当前不是 NFS rootfs。
```

补充说明：

```text
printenv bootargs 返回 not defined 是正常现象。
原因是当前环境没有常驻 bootargs 变量；bootargs 在执行 `run mmcboot` 时，由 `run mmcargs` 临时生成：
console=${console},${baudrate} root=${mmcroot}
也就是：
console=ttymxc0,115200 root=/dev/mmcblk1p2 rootwait rw
```

初步判断：

```text

优先检查物理链路：网线、插入的网口、对端交换机/路由器端口、网口灯。
如果 Linux 阶段 eth0/eth1 也持续 link is not ready，则更支持物理链路或网口选择问题。
```

补充排查记录：


最终解决方法：

```text
1. 将开发板网线接到有物理链路的网口，Linux 下表现为 eth0 LOWER_UP。
2. Windows Realtek 设置静态 IP 192.168.77.1/24，避开 VMware VMnet8 的 192.168.88.0/24 网段。
3. VMware VMnet0 桥接到 Realtek PCIe GbE Family Controller，并确认 VMware Bridge Protocol 已勾选。
4. Ubuntu ens33 设置静态 IP 192.168.77.132/24。
5. 开发板 Linux 中关闭无载波的 eth1，只保留 eth0=192.168.77.200/24。
6. 先 ping Windows 192.168.77.1，再 ping Ubuntu 192.168.77.132，均成功。
```

Ubuntu 固定 IP 命令：

注意：在 Ubuntu 虚拟机终端执行，不是在 IMX6ULL 的 `[root@100ask:~]#` 终端执行。

如果已有 NetworkManager 连接：

```bash
CON=$(nmcli -t -f NAME,DEVICE con show --active | awk -F: '$2=="ens33"{print $1; exit}')
sudo nmcli con mod "$CON" ipv4.method manual ipv4.addresses 192.168.77.132/24 ipv4.never-default yes ipv4.ignore-auto-dns yes connection.autoconnect yes
sudo nmcli con down "$CON"
sudo nmcli con up "$CON"
ip -br addr show ens33
```

如果 `$CON` 为空，创建新连接：

```bash
sudo nmcli con add type ethernet ifname ens33 con-name ens33-static ipv4.method manual ipv4.addresses 192.168.77.132/24 ipv4.never-default yes ipv4.ignore-auto-dns yes connection.autoconnect yes
sudo nmcli con up ens33-static
ip -br addr show ens33
```

实际最终使用 netplan 固定成功：

```bash
sudo chmod 600 /etc/netplan/01-network-manager-all.yaml
sudo tee /etc/netplan/99-imx6ull-ens33-static.yaml >/dev/null <<'EOF'
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:
      dhcp4: no
      dhcp6: no
      addresses:
        - 192.168.77.132/24
      optional: true
EOF

sudo netplan generate
sudo netplan apply
ip -br addr show ens33
```

结果：

```text
ens33 UP 192.168.77.132/24
```

板端重启后的注意事项：

```text
Ubuntu ens33 固定后，IMX6ULL eth0 的 192.168.77.200/24 仍可能不是持久配置。
如果板端 ping 192.168.77.132 出现 Network is unreachable，先重新配置板端 eth0。
```

